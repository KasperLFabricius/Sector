# PR-08D.3a CT-010a reinforcement-fatigue acceptance

This matrix freezes the unpublished reinforcement-fatigue evidence slice from
retained main mechanics. Sector remains `0.91`. The family is
`ct-010-reinforcement-fatigue`; concrete-fatigue verdict evidence remains
outside this slice.

| Family or invariant | Frozen acceptance |
| --- | --- |
| Applicability | `fatigue_on=False` is inapplicable and cannot carry CT-010a evidence. Active successful fatigue produces CT-010a only when the exact retained `fatigue_check_steel` Boolean is true. A concrete-only successful candidate is fully replayed and shape-validated before returning inapplicable. Retained invalid fatigue output produces one failed member, including when its caller-supplied error tuple is empty. |
| Inventories | A successful candidate is an exact built-in `dict` in the ordered `SUCCESS_KEYS` inventory. An invalid candidate is an exact built-in `dict` in the ordered `INVALID_KEYS` inventory. The contract tests freeze both inventories and their cardinality directly; no prose-maintained key count is authoritative. Missing, additional, duplicate, reordered, or differently typed retained structure fails closed. |
| Input identity | The normalised-input node seals presence, order, retained type, and exact value for every CT-010a input: raw controls and partial factors; spectrum rows including descriptions; complete concrete, bar, tendon, fatigue-detail, mild-material and prestress-material identities; element tables; and an immutable section vector of concrete-ring vertices plus ordered reinforcement coordinates and areas. Geometry scalars are fingerprinted in their original retained types without numeric coercion. Every identity leaf reaches every applicable member final. |
| Replay boundary | Successful output is replayed through `fatigue_analysis.run_analysis`. Reinforcement values and identities are exact. Concrete-only sibling values are excluded, but their presence, position, concrete dataclass/mapping/sequence shape, cardinality, and recursively retained types are pinned. Incompatible replacements for `concrete_method`, `concrete_parameters`, concrete results, search output, or aggregate siblings fail closed. |
| Elastic join | Each reinforcement assessment is joined by spectrum position, bin position/name, and element position to the authoritative retained `FatigueBinState`. Cycles, convergence, bond method/factor, long stress, fatigue-total stress, design fatigue-total stress and perfect-bond stress are derived from that matched state vector. Candidate assessment stresses are comparisons only and cannot become an alternative numerical authority. |
| Reinforcement proof | Stress ranges, design range, exact two-slope S-N selection, logarithmic life, Palmgren-Miner damage, design proof-stress limit, absolute-stress utilisation, governing bin identities, convergence and PASS/FAIL are independently reconstructed from the matched state and resolved fatigue properties. Damage is evaluated in the log domain so finite, zero, overflow, positive-infinity, negative-infinity, undefined and failed states are represented without fabricated finite substitutes. |
| Aggregation | Every assessment contributes to the spectrum and family closure. The member final binds the normalised input identity, raw `gamma_s`, `gamma_ff` and `gamma_c`, resolved reinforcement-property identity, all bin damage/yield/convergence proofs, governing identities and verdict. The aggregate final binds every assessment, every spectrum governing identity, all raw factors, global utilisation, convergence and worst-first status. |
| Sources | S-N and proof-stress nodes use the selected retained DS/EN 1992-1-1 edition and exact clause/table citations. Input identity uses input provenance. Boundary normalisation, matched Elastic-bin replay and verdict aggregation are uncited Sector project methods. Concrete-fatigue numerical values acquire no CT-010a provenance. |
| Hostile closure | Reject stale input/result hashes; invalid bundle seals; coherent reseals; source, unit, axis, order, dependency and final tamper; successful mapping subclasses; wrong output inventory; property, stress, bin, geometry, material, description and geometry-type substitutions; malformed exact Booleans; invalid-error type/order changes; concrete sibling type/cardinality replacement; and unrelated evidence on an inapplicable input. |

Hard exclusions: concrete-fatigue numerical proof (CT-010b), SLS/crack-width
evidence (CT-009/CT-009b), chord/off-util/biaxial joins, CT-002 sweep joins,
UI/report/manual/publication/persistence/package/schema/workflow/version changes,
F-020, solver/formula changes, and all rejected-head work.
